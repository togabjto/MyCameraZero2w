# Web アプリ（`src/webapp.py`）

設置したカメラを、SSH で起動して放置し、**ブラウザから**操作するための常駐アプリ。

- 監視の開始・停止
- ライブ映像（320x240・白黒。検知用の映像）と、「録画中」の表示
- 録画の一覧・再生（再生・一時停止・10 秒とばし・倍速）
- 稼働状況、録画の件数、ディスクの空き、ログの表示

## 使い方（Pi 上で）

```
cd ~/MyCameraZero2w
make -C src
tmux                                                    # SSH が切れても止まらないように
TOOLS_PASSWORD=好きな文字列 python3 src/webapp.py --autostart
# Ctrl+B → D で tmux から抜けて、SSH を切ってよい（戻るときは tmux attach）
```

同じ LAN のブラウザで `http://<Pi の IP>:8000/` を開く（ユーザー名: `admin`）。

| 画面 | 内容 |
|---|---|
| `/`（ホーム） | 状態、開始・停止ボタン、ライブ映像、ディスクの空き、ログ |
| `/recordings` | 録画の一覧。クリックで再生 |

主なオプション:

| オプション | 内容 |
|---|---|
| `--autostart` | Web アプリの起動と同時に、監視も開始する |
| `--workdir DIR` | 録画（`DIR/movie/`）とログ（`DIR/logs/`）の場所。既定は、今いるフォルダ |
| `--port N` | Web アプリのポート。既定: 8000 |
| `--pixel-threshold`, `--change-ratio` | 監視の感度（`surveillance.py` と同じ） |

## 動体検知メーター

ホームのライブ映像の下に、**今、動体検知がどれくらい反応しているか**を表示する（監視が動いているときだけ）。
感度（しきい値）を決めるときや、「録画が終わらない」ときの原因（本当に動いているのか、誤検知なのか）の切り分けに使う。

- **バー**: 前のフレームとの差が `pixel_threshold`（既定 30）を超えた画素が、画面全体の何 % か。
  **黒い線がしきい値**（`change_ratio`、既定 3%）。線を超えると、バーが赤くなり、「動き」と判定して録画する。
- **グラフ**: 直近 60 秒の推移（破線がしきい値）。
- 値は「直近 1 秒の最大」。毎秒十数回のフレームの、短い spike を、画面の更新の間で見逃さないため。
- 静止しているのに、バーが頻繁にしきい値を超えるなら、誤検知（明るさの揺れなど）。感度を下げる
  （`--change-ratio` を上げる、`--pixel-threshold` を上げる）。
- バーの右端は、しきい値の 2 倍か、最近の最大値（大きい方）に合わせて、自動で変わる。
- 画面は 0.5 秒ごとに値を取得する。TODO: この取得による、Pi の CPU への影響は未計測。

### 感度（しきい値）の調整

メーターの下の「感度の調整」のスライダーで、しきい値を変えられる。**動かすと、すぐ（約 0.5 秒後）に反映して保存する。カメラの再起動や、録画の中断は要らない。**

| 項目 | 範囲 | 既定 | 意味 |
|---|---|---|---|
| 画素差 | 0〜255 | 30 | 前のフレームとの明るさの差が、これを超えた画素を「変化した画素」と数える |
| 変化した画素の割合 | 0.1〜20%（コマンドでは 0 より大きく 1 以下） | 3.0% | 変化した画素が、画面のこの割合を超えたら「動き」とみなす |

- どちらも、小さいほど敏感（小さい動きや、ノイズにも反応する）。大きいほど鈍感（小さい動きを見逃す）。
- 調整のしかた: 静止しているときのバーの最大値より上、動いたときの値より下に、黒い線（割合のしきい値）が来るようにする。
  画素差を上げると、明るさの揺れによるノイズが、「変化した画素」に数えられにくくなる。
- 「既定に戻す」で、30 / 3.0% に戻る。
- 値は `workdir/settings.json` に保存され、次回の起動でも使われる。監視が止まっているときに変えた値は、次の開始から使われる。
- 仕組み: Web アプリが、監視（子プロセス）の `127.0.0.1` 限定の窓口に値を送る。監視は、**ループの中で**適用する
  （C の変数を、別のスレッドから書き換えると、読み取りが不整合になりうるため）。範囲外の値は、画面でも、Web アプリでも、監視でも拒否する。

## カメラの向き（回転・反転）

ホームの「カメラの向き」で、向きを変えられる。**ライブ映像を見ながら**直す。

| 設定 | 内容 |
|---|---|
| 向き | 0°（そのまま）／ 180°（上下逆さまに設置したとき） |
| 左右反転・上下反転 | 鏡のように映るときなどに使う。180° と組み合わせると、その分が打ち消し合う |

- 「**保存して再起動**」: 設定を保存して、カメラを再起動して反映する（録画中なら、保存してから再起動）。停止中なら、監視を開始する。
- 「保存のみ」: 設定だけ保存する。次にカメラを起動したときから反映される。
- 設定は `workdir/settings.json` に保存されるので、Web アプリを再起動しても残る（しきい値も同じファイルに保存される）。
  ファイルがない・壊れている場合は、起動時の `--rotation` / `--hflip` / `--vflip`（既定は 0°・反転なし）になる。
- コマンドからも指定できる: `python3 src/surveillance.py --rotation 180`（`tools/preview.py` も同じ）。
- カメラの ISP（ハードウェア）で反転するので、CPU の負荷は増えない（TODO: 実測は未実施）。

**90° / 270° には対応していない。** Raspberry Pi の ISP が対応するのは、上下・左右の反転だけで、縦横の入れ替え（転置）ができない。
縦向きに設置する場合は、今のところ、横向きの映像になる。対応するなら、再生時に回転させる方法（動画に回転の情報を付ける）などが考えられるが、未実装。

## 仕組み

- Web アプリが、`surveillance.py` を**子プロセス**として起動・停止する。
- 停止は Ctrl+C と同じ信号（SIGINT）。**録画中に止めると、MP4 に保存してから終わる**（最大 30 秒待ち、それでも終わらなければ強制終了）。
- ライブ映像は、子プロセスが `127.0.0.1` だけで配信し、Web アプリが中継する。LAN には直接出ない。
- パスワードは、子プロセスにコマンドライン引数ではなく、環境変数で渡す（`ps` に出ない）。
- Web アプリを止める（Ctrl+C や `kill`）と、子の監視も止まる。

## 注意

- **パスワード必須。通信は HTTP（暗号化されない）なので、LAN の中だけで使う。ルーターのポート開放はしない。**
- 開始・停止の操作は、別のサイトから勝手に実行されないよう、画面の `fetch` だけが付けるヘッダーと `Origin` を確認している。
- **このアプリが起動した監視だけを管理する。** 別に `surveillance.py` を動かしていると、カメラが使えず、失敗する（ログに出る）。
- **録画の自動削除はない。** ホームのディスク空きを、ときどき確認する（使用率が 90% 以上で警告が出る）。
- **監視が異常終了しても、自動では再起動しない。** ホームの状態が「停止」になり、前回の終了コードが出るので、ボタンで再開する。
- Pi の電源を入れ直すと、Web アプリも止まる（起動時の自動実行は未設定）。
- 録画の保存先が、今までの `src/movie/` と違う場合は、`--workdir src` を指定するか、ファイルを移す。
